# Playing in 2D

**Draft, 2026-09-29. Nothing built.** How a mouse-and-keyboard player does everything a VR player does.

## Rules this has to keep

- **Everything VR can do, 2D can do.** Same ship, same parts, same outcomes. No 2D-only shortcuts that
  do more than a hand could.
- **Worse informed, not compensated** (`principles.md` §12). No status panel, no HUD readouts, no
  highlighting of faults. The only additions on screen are the interaction affordances below (what can
  be clicked, and where a thing can go), and they appear only on the thing being worked on, just as the
  VR hologram does.
- **They walk the ship.** Everything is clicked from within reach, never from across the room, so a
  2D player still has to go to the reactor to read it.
- **Same networking as VR.** Every 2D action ends in the same call its VR version makes (see
  Networking), so authority, late joiners and what others see do not change.

## Controls

Movement and looking are Somnium's own desktop controls. Ours sit on top:

| Input | Does |
|---|---|
| **Left click** | Interact with what is under the cursor: press, pick up, select, place |
| **Right click** | Back out one step: cancel a selection, else close the open conduit |
| **Scroll wheel** | Turn what is selected or hovered: a dial, a held addon's twist |
| **G** | Drop what you are holding where you stand |
| **Esc** | Close the open conduit, dropping any selection |

**One hand.** A 2D player holds at most one thing, shown in the lower right of the view. VR's second
hand is only ever needed to hold a conduit open, and 2D replaces that with a conduit that stays open
until closed (below).

**Reach: about 2 m** from the camera (to tune). Out of reach, nothing highlights and clicks do nothing.

**Hover:** the thing under the cursor gets an outline when it can be clicked. That is the only cue;
no labels.

## Everything but conduits

| Thing | VR | 2D |
|---|---|---|
| Rocker switch | push the raised half | **click** it: it rocks over, with the same snap and sound |
| Reactor dial / rod lever | grab and turn or drag | **hover and scroll**, one notch per step; **click and drag** up or down for large moves. Scram is dragging it to zero |
| Slot handle | grab the bar and pull it out | **click** it: the bar animates out and back, and the slot unlocks as if pulled |
| Unlock cube (switch conduits) | pass a hand through it | **click** it |
| Addon item, loose | grab it | **click** to pick up; **G** drops it, and it falls like a released one |
| Component, unlocked | grab it and carry it, full size | **click** to pick up (below) |
| Petting Felix, some day | stroke him | **click and hold** |

### Carrying a component

A component is up to 5 m across (S5), so held in front of the camera it would hide everything. Carried in
2D it **shrinks to a small held model in the lower right**, and the world shows nothing where it was.

- **Placing:** aim at an empty slot. A **ghost of the component appears seated in the slot**: green if
  it is the slot's size, red if not. **Click** a green ghost to install it: it is the same install a VR
  hand makes, so it is seated, locked and wired the same way.
- **Dropping:** **G** puts it down full size on the floor in front of you.
- **Pulled out while live** loses 10% integrity (`grid.md`), exactly as in VR.

## Conduits

The complicated one. The same hologram opens, with the same parts; only the way of moving them
changes. Where VR drags, 2D **clicks to pick, then clicks where it goes**.

### Opening and closing

- **Click a conduit** in reach to open it. The hologram appears exactly as in VR, and other players
  see it held open the same way. A conduit with an unlock cube needs the cube clicked first.
- It **stays open** until you **right click** on nothing, press **Esc**, click another conduit, or walk
  out of reach. This stands in for VR's holding hand.

### Segments

Each segment in the hologram has its **handle** at the tip and its **arrow** along it, as in VR.

- **Moving a segment:** click its handle to select it. **Red dots** appear on every face it can move
  to (every free face, never one another segment is on), plus **one in the middle** for parking.
  Click a dot to move the segment there. Right click cancels.
- **Parking:** click the middle dot. The handle sits in the middle, as in VR.
- **Unparking:** click the parked handle in the middle; dots appear on the free faces. It comes back
  paired with its neighbour (Out toward a neighbour's In, In toward a neighbour's Out, else Out), the
  same rule as dragging it out in VR.
- **Direction:** click the **arrow** to flip it between **In** and **Out**. VR's third way (sliding
  across to park) is the middle dot above, so the arrow only ever flips.

### Addons

- **Installing:** hold an addon item and **click the empty addon slot** in the open hologram. It
  installs as if let go there.
- **Taking out:** with nothing held, **click the item in the addon slot**. The addon comes off the
  cable and the item is now what you hold. With a hand already full, the click does nothing.
- **Moving a repositionable addon** (the switch's capsule handle): click it to select it. Dots appear
  on its free faces and in the middle (park). Click a dot to move it there. While it is selected,
  **scroll** to twist it a quarter turn per notch, the same ticks as a VR wrist twist.

### When a change takes effect

Each finished click (a segment moved, an arrow flipped, an addon placed or moved) commits exactly as
releasing the matching VR handle does. Nothing waits for the conduit to close, and nothing is lost if
it closes mid-selection: a picked handle that was never placed simply stays where it was.

## Networking

Settled by the rule that **a 2D action is a VR action with a different trigger**. Each one ends in the
call its VR version already makes, so nothing new is decided about who owns what:

| 2D action | Same call as VR |
|---|---|
| Click a slot handle | `ComponentSlot.Pull()` (the master decides the lock) |
| Scroll / drag the dial | the reactor dial's hand-turned path (sent to the master) |
| Commit a hologram edit | the hologram's commit (`ConduitNetwork.DescribeEdit` → master `ApplyEdit`) |
| Install / take out an addon | the hologram's install and take-out |
| Open / close a conduit | the hologram occupancy, so no one else can open it meanwhile |
| Install a component | `ComponentSlot.Install` through the slot's network path |

**What others see must match VR's.** A held item is visible in the carrier's hand in VR; in 2D the
item or component being carried must still be shown to other players, carried in front of the 2D
player's avatar, so nobody's work happens invisibly. The dots, the placement ghost and the hover
outline are **local only**, like a VR player's hologram preview.

## Open

- **How Somnium hands mouse input to a world in desktop mode:** a ray from the camera through the XRI
  interactables we already have, raw input for our own scripts, or both. This decides how much of the
  above is built on the existing interactables and how much is new.
- **How a world script tells a desktop player from a VR one.** Somnium's log records the mode
  (`MODE_XR`); whether a world can read it is unknown.
- **Which keys Somnium already uses on the desktop**, so ours (G, Esc, scroll) do not collide.
- **The training room** teaches with ghost hands; 2D players need boards that show clicks instead.
